# PRD 1단계 — 냉장고 사진 식재료 인식

> 전체 흐름: **1단계 식재료 인식** → [2단계 레시피 생성](PRD_step2.md) → [3단계 프로필·레시피 저장](PRD_step3.md)

## 1. 목적

사용자가 냉장고 안을 찍은 사진을 올리면, 비전 모델이 사진 속 식재료를 찾아 목록으로 돌려준다. 이 목록은 2단계 레시피 생성의 입력이 된다.

## 2. 범위

**포함**
- 사진 업로드(파일 선택, 모바일 카메라 촬영)와 미리보기
- 비전 모델 호출을 통한 식재료 인식
- 인식 결과 표시와 사용자 수정(추가·삭제·이름 변경·수량 편집)

**제외**
- 레시피 생성(2단계), 로그인·저장(3단계)
- 유통기한 인식, 영양 분석, 여러 장 사진의 병합

## 3. 사용자 스토리

1. 사용자로서 냉장고 사진을 올리면 어떤 재료가 있는지 자동으로 목록을 받고 싶다.
2. 사용자로서 인식이 틀린 항목을 직접 고치거나 빠진 재료를 추가하고 싶다.
3. 사용자로서 확인한 목록으로 바로 레시피 추천 단계로 넘어가고 싶다.

## 4. 기술 구성

| 항목 | 결정 |
|---|---|
| 앱 | Python + Streamlit (화면과 서버 로직이 한 프로세스) |
| 배포 | Streamlit Community Cloud (무료) |
| 모델 | `nvidia/nemotron-3.5-super-vl:free` |
| 호출 | OpenRouter `https://openrouter.ai/api/v1/chat/completions` |
| 이미지 전달 | base64 data URL (사전 테스트로 동작 확인됨) |

**API 키 보안 원칙**
- `OPENROUTER_API_KEY`는 서버만 읽는다. 읽는 순서는 `st.secrets` → 환경변수 → 프로젝트 루트 `.env`이다.
- 배포 환경에서는 Community Cloud 앱 설정의 Secrets 칸에 키를 넣는다. 로컬에서는 `.env` 또는 `.streamlit/secrets.toml`(git 제외)을 쓴다.
- Streamlit 코드는 서버에서만 실행되므로 키가 브라우저로 내려가지 않는다. 화면, 오류 문구, 로그에 키를 출력하지 않는다.

## 5. 기능 요구사항

### 5.1 이미지 업로드
- 허용 형식은 JPEG, PNG, WebP이며 업로드 최대 크기는 10MB이다.
- 서버는 Pillow로 형식을 실제로 검증하고, 긴 변 기준 1024px 이하로 줄인 뒤 JPEG로 재인코딩해 모델에 전송한다. 용량이 300KB를 넘으면 화질(85→55)을 낮추고, 그래도 크면 크기를 20%씩 줄인다. (토큰·지연·제한 위험을 줄이기 위함)
- 줄이는 작업은 업로드가 서버에 도착한 뒤 모델에 보내기 전에 한다. 브라우저에서 미리 줄이려면 별도 컴포넌트가 필요해 이번 범위에서 제외한다. 대신 `.streamlit/config.toml`의 `maxUploadSize = 10`으로 10MB 초과 파일은 업로드 단계에서 거부한다.
- 화면에는 "사진을 ○○KB → ○○KB로 줄여 전송했습니다"를 표시한다.
- EXIF 회전 정보를 반영한다. 이미지 원본은 서버에 저장하지 않는다.

### 5.2 식재료 인식
- 서버는 비전 모델에 사진과 프롬프트를 보내고, 아래 JSON 형식으로만 답하게 한다.

```json
{ "ingredients": [ { "name": "달걀", "quantity": "6개", "confidence": "high" } ] }
```

- `name`은 한국어 일반 명칭, `quantity`는 대략적 수량(모르면 빈 문자열), `confidence`는 `high`/`medium`/`low`이다.
- 사진에 식재료가 아닌 것(용기, 가구 등)은 제외하도록 프롬프트에 명시한다.
- 서버는 응답에서 JSON을 추출·검증하고 실패하면 1회 재요청한다. 그래도 실패하면 오류로 처리한다.
- 같은 재료 중복은 이름 기준으로 합친다.

### 5.3 결과 확인·수정 화면
- 인식된 재료를 칩/목록으로 보여 주고 `confidence: low`는 시각적으로 구분한다.
- 사용자는 항목 삭제, 이름·수량 수정, 직접 추가를 할 수 있다.
- 확정 버튼을 누르면 확정된 목록이 2단계 입력으로 넘어간다. (이 단계에서는 서버에 저장하지 않고 화면 상태로 보관)

### 5.4 모듈 구성

Streamlit 앱에는 별도 HTTP 엔드포인트가 없으므로, 로직을 화면과 분리한 모듈 함수로 둔다.

| 위치 | 설명 |
|---|---|
| `src/recognizer.py` `recognize(raw_image, api_key)` | 이미지 바이트 → 식재료 목록(`name`, `quantity`, `confidence`). 검증·축소·호출·재시도·파싱 포함 |
| `src/app.py` | 업로드·카메라, 결과 표(수정 가능), 확정 버튼. 확정 목록은 `st.session_state["confirmed"]`에 보관해 2단계로 넘긴다 |

카메라 촬영은 토글을 켰을 때만 `st.camera_input`을 만든다. 만들어 두면 페이지를 열 때마다 카메라 권한을 요청하기 때문이다.

### 5.5 무료 배포(Streamlit Community Cloud)

- GitHub 저장소를 연결하고 메인 파일을 `src/app.py`로 지정한다. 의존성은 루트 `requirements.txt`를 쓴다.
- 일정 시간 접속이 없으면 앱이 잠들고, 다시 열면 깨어나는 동안 느릴 수 있다.
- 서버 디스크는 영구 저장소가 아니다. 이 단계는 저장하지 않으므로 문제없지만, 3단계에서는 외부 저장소가 필요하다.

## 6. 모델 호출 시 유의점 (사전 테스트에서 확인된 사실)

- 이 모델은 답변 전에 추론에 토큰을 많이 쓴다. `max_tokens`는 **2000 이상**으로 둔다. 300에서는 응답이 중간에 끊겼다.
- 무료 모델은 제공사 사정으로 429(속도 제한)·404가 날 수 있다.
  - 429(5xx 포함): 2초 뒤 한 번만 다시 시도한다.
  - 그래도 실패하면 대체 모델 목록(`recognizer.FALLBACK_MODELS`)을 순서대로 시도한다. 모델이 없거나(404) 사용 불가(403·410)인 경우도 다음 모델로 넘어간다. 대체 모델마다 같은 규칙(한 번 재시도)을 적용한다.
  - 대체 모델 목록은 덜 알려진 무료 이미지 모델 순이다. OpenRouter가 인기 순위를 API로 제공하지 않아 직접 정했고, 실제 이미지 호출로 동작을 확인했다. (`dots-studio/dots-3-note-preview:free` → `minimax/minimax-m3.1-flash:free` → `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`) 모델 가용성은 수시로 바뀌므로 주기적으로 확인한다.
  - 대체 모델로 인식했으면 화면에 그 사실을 알리고 결과를 꼼꼼히 확인하도록 안내한다. 대체 모델의 정확도는 기본 모델과 다를 수 있다.
  - 모든 모델이 실패하면 "지금 요청이 몰려 있습니다. 잠시 후 다시 시도해 주세요"를 보여 준다.
  - 401은 서버 설정 문제이므로 사용자에게는 일반 오류 문구를, 서버 로그에는 원인을 남긴다. 키 값은 로그에 남기지 않는다.
- 요청 타임아웃은 120초이다. 화면에는 진행 표시(스피너)를 보여 준다.

## 7. 비기능 요구사항

- **성능:** 정상 응답 기준 사진 1장 인식은 30초 이내를 목표로 한다. (무료 모델이라 보장하지 않음)
- **개인정보:** 업로드 이미지는 인식 요청이 끝나면 메모리에서 폐기하고 디스크·DB에 저장하지 않는다.
- **남용 방지:** 세션당 분당 5회로 요청을 제한한다. Streamlit에서는 방문자 IP를 안정적으로 얻기 어려워 IP 대신 세션 기준이다. 새로 고침하면 우회되므로 완전한 방어는 아니다.
- **접근성:** 모바일 화면에서 사용할 수 있어야 한다.

## 8. 오류 처리

| 상황 | 사용자 메시지 방향 |
|---|---|
| 지원하지 않는 형식·용량 초과 | 형식·크기 안내 |
| 식재료가 하나도 인식되지 않음 | 사진이 어둡거나 가렸을 수 있음을 안내하고 직접 추가 유도 |
| 모델 응답 JSON 파싱 실패 | 다시 시도 유도 |
| 429 / 타임아웃 | 잠시 후 재시도 안내 |

## 9. 수용 기준

- [ ] 냉장고 사진을 올리면 식재료 목록이 화면에 표시된다.
- [ ] 사용자가 목록을 수정·추가·삭제할 수 있다.
- [ ] 브라우저 개발자 도구의 요청·응답·소스 어디에도 API 키가 나타나지 않는다.
- [ ] 카메라 토글을 켜기 전에는 카메라 권한을 요청하지 않는다.
- [ ] 10MB 초과 파일과 이미지가 아닌 파일은 거부된다.
- [ ] 429가 나는 상황에서 재시도 후 친절한 오류 문구가 보인다.
- [ ] 확정한 목록이 2단계 화면으로 전달된다.

## 10. 미결 사항

- 인식 정확도를 어떻게 평가할 것인가? (예: 직접 찍은 사진 10장으로 수기 비교)
- 한 번에 여러 장(선반별) 업로드를 지원할 것인가? 현재는 1장으로 제한한다.
